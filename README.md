# Water Tours

Spring Boot 3.5.6 / Java 21. Основной план работ: [ROADMAP.md](ROADMAP.md).

## Проверка проекта

Требуются JDK 21 и запущенный Docker Desktop с Linux-контейнерами.
Из папки проекта в PowerShell:

```powershell
.\mvnw.cmd -B verify
```

Первый запуск скачивает зависимости и образы. Тест автоматически создаёт отдельные
PostgreSQL и Redis на случайных портах и удаляет контейнеры после проверки.
Рабочая БД, SMTP и платёжный API не используются. Проверяется запуск Spring,
создание таблицы orders и запись/чтение Redis. Это не проверка покупки целиком.
Без Docker проверка завершается ошибкой, а не пропускается.
Testcontainers 1.21.4 выбран для совместимости с Docker 29.

## Локальный запуск приложения

1. Запустить PostgreSQL и Redis: `docker compose up -d`.
2. Скопировать `.env.example` в `.env` в корне этого репозитория и заполнить локальными
   значениями. Для БД использовать значения из compose.yml. Для платежей — тестовый магазин.
3. Запустить:

```powershell
.\mvnw.cmd spring-boot:run '-Dspring-boot.run.arguments=--spring.config.import=file:./.env[.properties]'
```

Здесь файл загружается явно как Java properties: значения без кавычек и без `export`.
Само наличие dotenv-java в pom.xml не загружает файл автоматически.
Для файла вне репозитория предпочтительно задать переменные окружения в конфигурации
запуска IntelliJ; не переносить секреты в исходники. При запуске через IntelliJ можно
также указать тот же `--spring.config.import=file:./.env[.properties]` в Program arguments,
с рабочей папкой в корне репозитория.

Сервер: http://localhost:8080. Состояние: /actuator/health.
Текущий compose.yml — для локальной разработки, не для публичного сервера.
Hibernate пока использует ddl-auto=update; миграции и production-настройки — отдельный этап.
Не запускать тестовые эксперименты на базе с реальными заказами.
