# Подключение Яндекс Вебмастера и Google Search Console

Составлено 2026-09-15. **Ничего из этого не выполнено**: подтверждение сайта требует доступа к
аккаунту владельца и к DNS, которых у исполнителя нет и не должно быть. Это чек-лист для
владельца или для отдельной авторизованной задачи.

Порядок важен: сначала проверить, что подтверждать (раздел 1), потом подтверждать.

## 0. Что уже готово в коде (проверено локально)

- Один `<title>` и одно описание на главной; на служебных представлениях (поиск по сайту, 404,
  архивы по датам/авторам/меткам, страницы пагинации) — `noindex,follow`.
- `rel=canonical`: на singular-страницах его ставит ядро WordPress, тема его не дублирует; на
  остальных представлениях canonical ставит тема.
- Open Graph и `twitter:card` — для превью ссылки в мессенджерах.
- JSON-LD: Organization, WebSite и две услуги с **реальными** ценами из бэкенда.
- `robots.txt` дополнен запретом обхода `/api/`, `/staff`, `/t/`, `/checkout.html`, `/login`.
  Это не защита — доступ к ним закрывают токен и логин.
- `wp-sitemap.xml` генерирует ядро; провайдер `users` отключён.

Всё это отключается само, если на сайте появится SEO-плагин (Yoast, Rank Math, SEOPress,
AIOSEO, The SEO Framework) — два комплекта тегов хуже, чем один.

## 1. Перед подтверждением — проверить на живом сайте

```bash
curl -sI https://water-tours.ru/            # 200, один домен
curl -sI https://www.water-tours.ru/        # 301 на основной домен (или наоборот - но один раз)
curl -s  https://water-tours.ru/robots.txt  # есть Sitemap: и наши Disallow
curl -s  https://water-tours.ru/wp-sitemap.xml | head -20
curl -s  https://water-tours.ru/ | grep -E 'canonical|og:|application/ld\+json' | head
```

- [ ] Выбран **один** основной домен (с `www` или без) и второй на него редиректит.
- [ ] HTTPS везде, HTTP редиректит на HTTPS.
- [ ] `robots.txt` отдаётся и содержит строку `Sitemap:`.
- [ ] `wp-sitemap.xml` открывается и содержит только реальные страницы.
- [ ] В выдаче `curl` главной видно ровно один `canonical`, один `og:url`, один блок JSON-LD.
- [ ] Проверить JSON-LD в [валидаторе schema.org](https://validator.schema.org/) и в
      [Rich Results Test](https://search.google.com/test/rich-results) — ошибок быть не должно.
      Отсутствие «rich result» — это нормально: разметка здесь описывает услуги, а не претендует
      на значок в выдаче.

## 2. Яндекс Вебмастер

1. [ ] Войти под аккаунтом владельца (**не** под аккаунтом исполнителя — сайт должен остаться у
       владельца при любой смене подрядчика).
2. [ ] Добавить сайт, выбрать способ подтверждения:
       - **DNS TXT** — предпочтительно: переживает смену темы, хостинга и плагинов.
       - HTML-файл в корне — потребует доступа к серверу.
       - Мета-тег — потребует правки темы; если выбран этот способ, тег добавлять через фильтр
         `wp_head`, а не вписывать в шаблон руками.
3. [ ] Подтвердить и дождаться проверки.
4. [ ] «Индексирование → Файлы Sitemap» → добавить `https://water-tours.ru/wp-sitemap.xml`.
5. [ ] «Настройка → Регион сайта» → Санкт-Петербург.
6. [ ] «Диагностика» — записать все замечания как есть, ничего не «чинить» вслепую.

## 3. Google Search Console

1. [ ] Ресурс типа **Домен** (DNS-подтверждение) — покрывает оба поддомена и оба протокола сразу.
       Если DNS недоступен — ресурс с префиксом URL для выбранного основного домена.
2. [ ] Sitemaps → `wp-sitemap.xml`.
3. [ ] «Проверка URL» для главной → «Запросить индексирование».
4. [ ] Через несколько дней: отчёт «Страницы» — какие URL исключены и почему. Ожидаемо
       исключёнными должны быть только те, что помечены `noindex`.

## 4. После подтверждения — что записать

Индексация не наступает от того, что сайт добавлен. Зафиксировать дату подтверждения и потом
отдельно — дату, когда главная реально появилась в индексе каждой системы. Это два разных факта,
и путать их не нужно.

## 5. Чего здесь сознательно нет

- **Карточка Яндекс Бизнеса.** Требует подтверждённого адреса и типа организации. Причал — не
  офис компании, а фактический адрес не подтверждён. Пока адрес и телефон не подтверждены
  владельцем, карточку заводить нельзя: неверные данные в справочнике хуже их отсутствия.
- **Отдельные страницы маршрутов.** Требуют подтверждённых фактов (причал, расписание,
  длительность). Список нужных фактов — в отчёте `target/LAUNCH-READINESS-RESULT.md`, раздел
  «что нужно от владельца».
- **Покупка ссылок и массовая регистрация в каталогах** — не делается.
